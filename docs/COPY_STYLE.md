# 公开文案规范

本规范适用于正式页面中的站方自编文字，包括世界入口、专题摘要、按钮、状态提示、空状态、剧透提醒和来源说明。官方标题、专有名词、直接引用、资料原文、事件事实、日期、ID、URL 与来源归属不在润色范围内。

## 写作原则

1. **先说内容**：优先交代人物、地点、事件或可执行动作，避免向访客讲解数据合同、页面结构和实现方式。
2. **使用具体事实**：用“天灾迫使城市迁徙”一类可验证信息替代“命运被改写”“留下不可磨灭的痕迹”等泛化表达。
3. **保持 IP 差异**：明日方舟偏调查记录与工业感；战锤 40K 偏军情、航路与战区；最终幻想 XIV 偏旅途、水晶和群星，但不堆砌意象。
4. **一句只做一件事**：入口说明控制在一个核心判断和一个明确去向内；按钮直接写动作。
5. **说明只服务阅读**：剧透、资料状态、收录边界和无脚本降级可以说明；实现框架、统一数据、URL 规则和视觉设计不向访客展示。

## 禁止写法

- 先否定一个空泛判断，再用转折引出正文的模板句。
- 连续使用“改写、铭刻、回声、命题、足迹”等抽象词制造气氛。
- 把“规范记录、规范事件、数据结构、信息架构、接口、拓扑、模型边界、URL 语义”等维护术语写进访客文案。
- 为了显得简洁而删去事实限定、时间范围、来源状态或官方/站方边界。
- 仅替换连接词，保留原句的模板结构。

## 分批验收

每批文案修改均执行以下检查：

1. 阅读差异，确认改动只落在站方自编文字。
2. 对照原文核验人物、术语、数字、日期、链接和事实关系。
3. 扫描模板化否定转折与访客不可见的维护术语。
4. 运行 `node --test tests/copy-style.test.js` 与 `git diff --check`。
5. 完成全部批次后运行生产构建和完整测试，并在浏览器中检查实际断行、按钮长度与页面语气。
