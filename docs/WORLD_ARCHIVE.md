# 世界档案架构

> 本文扩展产品领域模型与世界页面边界；构建工具、静态多页形态和既有 UI / Engine / Data 依赖方向仍以 `docs/ARCHITECTURE.md` 为准。旧文档中的“编年史”路径视为时域镜的技术说明；涉及产品定位或多观测镜时，以本文为准。

## 定位

“群星之间”是一套连接多个虚构世界的观测与调查系统。

每个世界只有一份规范事实集合。访问者可以从档案问题、人物与概念关系、编年顺序等不同入口阅读这组记录。某个 IP 的视觉语言可以非常鲜明，但视觉层不能拥有或修改第二份事实数据。

## 统一模型

| 术语 | 含义 |
| --- | --- |
| `WorldArchive` | 编译并查询单个世界规范记录的领域核心 |
| `CanonicalRecord` | 拥有稳定 ID 的事件或结局记录，是所有观测镜共享的事实单位 |
| `Context` | 记录所在的语义范围，可表示主线、活动、假设条件或嵌套分支；不强制等同于“世界线” |
| `Dossier` | 围绕一个调查问题组织的记录引用，不复制记录正文 |
| `Lens` | 对同一世界记录的阅读方式，例如档案、关联、时域 |
| `ObservationSnapshot` | `WorldArchive.explore(request)` 返回的语义快照 |
| `Adapter` | 将语义快照翻译成某个 IP 的页面结构、视觉和交互 |

核心公开接口只有一个：

```js
const archive = createWorldArchive(worldData);
const snapshot = archive.explore({
  lens: 'dossier',
  dossierId: 'deep-blue-observation',
  focusId: 'if-mizuki-ending-3'
});
```

深接口的目标是让页面无需理解递归分支、记录去重和引用校验。时间线旧组件通过 `timeline-adapter.js` 消费 `chronicle` 快照；明日方舟调查台通过 `arknights-archive.js` 消费 `dossier` 快照。

## 三层边界

```text
世界 JSON
  └─ WorldArchive（规范记录、上下文、档案引用、校验）
       └─ ObservationSnapshot（档案 / 关联 / 时域）
            └─ IP Adapter（结构、动效、声音策略、页面风格）
```

这条边界同时解决两个看似冲突的要求：

- 内部一致：所有观测镜共享同一个 `CanonicalRecord` 对象和稳定 ID。
- 外部发散：明日方舟可以是工业调查终端，战锤 40K 和最终幻想 XIV 后续可以建立完全不同的呈现语言。

## 数据规则

1. 所有事件和结局必须有稳定且全世界唯一的 ID。
2. `Dossier.records` 只能引用规范记录，不能内嵌另一份事件正文。
3. 上下文 ID 必须唯一；父子关系、分歧点和状态元数据在投影时必须保留。
4. 结局不必被解释成平行世界线。它可以是观测结果、假设记录、互斥证词或档案推演，具体语义由 `Context` 和 `Dossier` 表达。
5. 跨世界引用永远指向稳定记录 ID，不指向页面位置或视觉组件。
6. 构建遇到重复 ID、悬空引用或无稳定标识的结局时必须失败，不能静默忽略。

## 世界页面规则

全站外壳保持统一：站点导航、主内容地标、剧透与来源规则、键盘可达性、移动端正常阅读、错误恢复和 URL 深链接。

世界 Adapter 可以发散：配色、字体、构图、微动效、信息密度、卡片形态和专属术语。它不能改变记录事实、制造第二套分类真相，或让核心导航只能依赖某种 IP 特效工作。

Adapter 样式必须带 `.world-<id>` 外层作用域。体量较大的世界体验可以使用只在该页面加载的独立 CSS 文件，避免未来每增加一个 IP 都让所有世界下载同一份皮肤代码。

PC 是主要体验目标。手机使用线性布局完整呈现正文和操作，不追求低端设备的专门特效降级，也不把横向拖动作为阅读正文的必要条件。

## 内容与来源

- 正文使用原创摘要，不大段复制官方或社区条目。
- 正式记录必须保留可追溯来源；暂时无法核验的资料留在内容工作清单，不进入公开数据。
- 普通记录不展示冗余的可信度徽章，只有来源或解释状态例外时才显示标记。
- 页面应明确覆盖范围、更新时间和已知缺口，避免把未收录内容伪装成完整世界观。
- 收到权利人删除要求时，优先移除对应素材或摘要并保留数据结构。

## 新增世界清单

1. 为世界、上下文和记录分配稳定 ID。
2. 先接入 `WorldArchive` 并通过规范记录集合测试。
3. 选择第一个能代表该世界的调查问题，建立只含引用的 `Dossier`。
4. 设计独立 Adapter；不要复制明日方舟的工业皮肤。
5. 加入键盘、剧透、来源、深链接、手机顺序阅读和无脚本回退检查。
6. 确认档案与时域快照的记录 ID 集合完全一致后再发布。

## 当前纵向切片

- 明日方舟：泰拉总入口、独立主编年、七个集成战略专题。七个专题共享语义骨架，但分别采用梦境、舞台、深海、极地、残片、界园和黑流树海的拓扑与皮肤。
- 战锤 40K：银河入口、规范编年、九大阵营索引与六大战区。阵营和战区是同一组记录的两种 Lens。
- 最终幻想 XIV：水晶星海入口、唯一规范编年、十四镜界棱镜与八段旅途星座。镜像是空间—以太结构，旅途是叙事长弧，两者都不复制记录正文。

新的世界可以采用其他形态。纵向切片应先寻找该 IP 最有辨识度的探索动作，再将其实现为新的 Lens 或 Adapter，避免预设“世界线”模板。
