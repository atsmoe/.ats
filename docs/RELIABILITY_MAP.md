# 完善与可靠性决策地图

目标：在不改变现有内容和视觉体验的前提下，让项目更快、更稳定、更容易由单人长期维护。

默认原则：

- 用户负责产品方向与内容取舍；技术方案、风险控制和验证由维护代理负责。
- 每次只处理一个可验证的小目标，完成构建与必要测试后再继续。
- 优先修复代码与文档已经明确冲突的部分，不把大规模重构作为起点。
- 不因优化删除源数据、原始素材或用户内容；涉及取舍时先说明影响。
- 动画、交互和视觉表现是网站展示技术力的核心，不以简单删减特效换取性能；通过独立加载、自适应质量和帧预算保证流畅。
- 视觉方向采用原创的深色工业、终端界面、几何切割和世界主题色体系，可参考鹰角网络作品的设计方法，但不复制其素材、布局或品牌识别元素。
- 每次推送到 GitHub 必须同时维护面向访客的更新日志和面向维护的开发日志，并由 CI 强制检查。
- 面向用户的汇报只包含结果、可见影响、风险和下一步，不要求理解代码。
